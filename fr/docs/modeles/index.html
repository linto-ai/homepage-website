Vos propres modèles de documents pour les comptes rendus et résumés

LinTO Studio transforme une transcription en compte rendu, en résumé ou en verbatim, puis l'exporte. De base, vous avez du DOCX, du PDF, du TXT et du JSON. Avec un modèle, l'export sort directement dans votre mise en page Word : logo, titres, polices, pied de page. Ça prend une dizaine de minutes à mettre en place, sur les plans Premium et Business. En Gratuit, comptes rendus et résumés utilisent les modèles LinTO et sortent en PDF.

1. Partez d'un document Word que vous utilisez déjà

Prenez le fichier que votre équipe remplit déjà à la main : le modèle de compte rendu, le papier à en-tête, le squelette de rapport. Gardez ses styles, son en-tête et son pied de page. Le modèle doit être un fichier DOCX de moins de 10 Mo.

2. Placez le champ de contenu

Écrivez {{output}} là où le texte de l'IA doit arriver. C'est le seul champ obligatoire. Le contenu généré garde sa structure (titres, listes, paragraphes) et prend les styles de votre document. Un modèle minimal ressemble à ça :

MEETING MINUTES

Project: {{title}}
Date: {{date}}

{{output}}

Minutes generated with LinTO Studio.

Les autres champs comme {{title}}, {{date}} ou {{participants}} sont facultatifs. Ils sont proposés dans un petit formulaire au moment de l'export pour que vous les remplissiez. Sur les déploiements gérés et sur site, ils peuvent aussi être extraits de la transcription par l'IA : demandez-nous de configurer un prompt d'extraction pour votre service.

3. Envoyez-le dans LinTO Studio

Ouvrez une transcription, générez un résumé ou un compte rendu depuis le menu des services IA, puis cliquez sur Publication et Envoyer un modèle. Donnez-lui un nom et choisissez qui le voit : vous seul, ou toute votre organisation. En Business, un modèle envoyé pour l'organisation est disponible pour chaque membre.

4. Aperçu, puis export

Sélectionnez le modèle et cliquez sur Aperçu pour vérifier le résultat sur le document en cours. Puis exportez en DOCX pour continuer à éditer dans Word, ou en PDF pour une version finale. Le PDF est rendu côté serveur avec LibreOffice : restez sur des polices courantes ou intégrez-les dans le DOCX.

Conseils

  • Faites un modèle par type de document : compte rendu, synthèse, verbatim. Chaque service IA peut être lié à ses propres modèles.
  • Gardez des tableaux et des colonnes simples. L'aperçu web ne rend pas les sauts de page, les zones de texte ni les mises en page multi-colonnes ; le PDF, si.
  • Un champ doit rester d'un seul tenant dans Word. Si Word coupe {{output}} entre deux changements de mise en forme, retapez-le d'une traite.
  • Les modèles vivent avec votre organisation. Renommez, remplacez ou supprimez-les depuis le même panneau Publication.

Pour les développeurs

Tout ce qui précède est disponible par l'API avec un jeton API : lister les modèles, lire leurs champs, exporter un document avec un modèle donné en DOCX, PDF ou HTML. Le moteur documentaire est le LinTO LLM Gateway, open source ; son guide des modèles de documents couvre les prompts d'extraction et les points d'entrée d'export.

Besoin d'un modèle conçu à votre charte, ou de l'extraction de champs précis (décisions, actions, échéances) ? Parlons-en.
